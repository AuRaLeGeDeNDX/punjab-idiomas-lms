Critical Production Fixes

1. Environment Configuration (.env)

Your application is currently configured for local development. For production, update .env:

  1. APP_ENV=production (currently: local)
  2. APP_DEBUG=false (currently: true) - CRITICAL: Never expose debug info in production
  3. APP_URL=https://your-domain.com (currently: http://127.0.0.1:8000)
  4. DB_HOST=your-production-db-host (currently: 127.0.0.1)
  5. DB_DATABASE=production_db_name
  6. DB_USERNAME=secure_username (currently: root)
  7. DB_PASSWORD=strong_password (currently: empty)
  8. MAIL_HOST, MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD

2. Remove All Debug/Test Files

Why: Debug files expose sensitive information and increase security risks.

How: Use the provided deployment scripts (deploy.sh or deploy.ps1) to automatically remove all debug files.

3. Database Configuration & Migration

Before deployment:

  1. Set up fresh MySQL database on VPS
  2. Update DB credentials in .env
  3. Run: php artisan migrate --force
  4. Seed if needed: php artisan db:seed

Deployment Steps

Step-by-Step Deployment Process

  1. Clone Repository
    git clone [your-repo] /var/www/lms
  2. Run Deployment Script
    cd /var/www/lms && bash deploy.sh
    This will automatically:
    • Remove all debug/test files
    • Install composer dependencies
    • Generate APP_KEY if needed
    • Set proper file permissions
    • Clear and cache configuration
    • Build frontend assets
    • Create storage symlinks
  3. Update Environment File
    Edit .env with production settings
  4. Run Migrations
    php artisan migrate --force
  5. Configure Web Server
    Configure Apache/Nginx to serve the public/ directory
  6. Set Up SSL
    Install and configure SSL/TLS certificate (Let's Encrypt recommended)
  7. Test Application
    Verify all functionality works correctly in production
  8. Enable Monitoring
    Set up log monitoring and alerts
